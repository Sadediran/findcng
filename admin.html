Admin passcode

Enter your role passcode. Super admin can do everything; data admin manages listing reports, availability and data quality; verifier reviews the operator queue and availability. Each role has its own passcode, set in the Vercel project settings (env ADMIN_PASSCODE, DATA_ADMIN_PASSCODE, VERIFIER_PASSCODE). The dashboard only shows the panels your role may use — the server enforces the same rules.

Overview — live counts

Every figure is counted live from the database or the directory — nothing here is estimated or hardcoded. “Not open yet” means the table for that feature has not been set up in Supabase.

Listing reports

Availability reports — recent history

The most recent availability reports, newest first. A ⚠ burst flag means one reporter filed 5+ reports in the last hour — check whether it is a flood, then delete the abusive rows. Deleting a report removes it from the live feed and from history. Saheed's own reports (CNG-018, CNG-021, CNG-009, 19 Nov) are real — do not delete them. Reports marked Operator confirmed were published by approving an operator submission.

Operator queue

Operator registrations, ownership claims, update requests, availability updates and responses to user reports. Nothing here is published until you approve that exact submission. Approving an availability update publishes it as an “Operator confirmed” report; approving anything else records the decision — the directory itself is static data, so apply the change in the master dataset and rebuild. A claim must never be approved without the verification checklist: check the documentation reference, confirm by phone, and check the business against official lists.

Audit log

Who did what, when — every admin action (resolve, dismiss, delete, operator approve/reject) is recorded with the role that performed it. There are no named accounts in this stack, so the role is the actor.

Data quality

Duplicate detection

Entries sharing the same coordinates (4 decimal places, about 11 m). Groups with an exact pin are flagged as possible duplicates of one physical place; coarse town/approximate groups are shared locality centroids and are expected. Nothing is merged here — merging happens in the master dataset, by Saheed's decision.

Accreditation review

Centres whose accreditation needs re-verification (stale 2024-list entries) and single-source entries. Re-verification means checking the centre against a current official source and updating the master dataset — it is not done from this panel.

How to handle a listing report

  1. Open the listing from the report and check what the user says is wrong.
  2. Where the report is right, fix the listing in the master dataset (~/workspace/cng-project/data/stations.json), re-run build-data.py, and redeploy.
  3. Then mark the report resolved here (with a note) — resolving here only closes the report, it does not change the listing.
  4. Dismiss reports that are wrong or abusive, with a note saying why.

How to verify an operator claim

  1. Check the documentation reference the operator gave (CAC registration, accreditation certificate, or similar) against the business name and the listing.
  2. Call the phone number on the submission and confirm the person runs that station — tick the checklist in the review sheet only for checks you actually did.
  3. Check the business against official lists (Pi-CNG registers) where possible.
  4. Approve only when the checks pass; reject with a reason when they do not. A rejected claim publishes nothing.
